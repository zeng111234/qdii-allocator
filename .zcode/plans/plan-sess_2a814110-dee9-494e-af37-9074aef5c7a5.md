## 问题分析

### 问题 1：邮件排名每个小数据都是 NaN

**根因**：`index.js:462-465` 在发送邮件前，用 `data/factor-rankings.json` 替换了 `result.ranked`。但 factor-rankings.json 的每条记录只有这些字段：

```json
{ "rank": 1, "code": "012920", "name": "...", "type": "...", "indexGroup": "...", "score": 38.6, "deduped": false }
```

**没有 `indicators` 字段**。而 `lib/mailer.js:48-58` 渲染邮件时访问 `f.indicators`：

```js
const ind = f.indicators || {};  // f.indicators 是 undefined → ind = {}
if (ind.annualizedReturn !== null) metrics.push("年化 " + ind.annualizedReturn + "%");
// ind.annualizedReturn 是 undefined，undefined !== null → true → 显示 "undefined%"
```

每个指标都变成 "undefined%"（用户看到的是 NaN 或乱码）。

### 问题 2：GitHub Actions 报错

由于无法直接访问 Actions 运行日志，根据代码分析最可能的原因：

1. **`npm run lint` 失败** — eslint 配置 `"no-var": "error"`，新测试文件可能含 `var`
2. **`npm test` 失败** — 新增的测试文件（`mailer.test.js`、`factor-engine.test.js` 等）可能引用了已变更的模块接口
3. **nodemailer 6→9 破坏性升级** — Dependabot PR #32 将 nodemailer 从 6.x 升到 9.x（TLS 验证行为变化），如果已合并会导致邮件发送失败

---

## 修复方案

### 修复 A：邮件 NaN（核心修复）

**修改 `index.js` 的 `sendReport` 函数**（~第 448-465 行）：

当使用 factor-rankings 替换 `result.ranked` 时，为每只基金补全 `indicators` 数据。具体做法：

1. 加载 `nav-cache.json`
2. 对 factor-rankings 中的每只基金，从 nav-cache 取净值数据
3. 调用 `fund-data.js` 的 `calcIndicators()` 计算技术指标
4. 将计算结果挂到 `f.indicators` 上

这样邮件模板就能正确显示年化收益、夏普比率、最大回撤等指标。

### 修复 B：邮件模板防御性检查

**修改 `lib/mailer.js`**：

- 第 49-58 行：增加 `ind.annualizedReturn !== undefined` 检查
- 第 139-145 行：增加 `rk.healthScore` 等的 NaN 检查
- 第 194-200 行：增加 `ps.totalInvested` 等的 NaN 检查
- 添加一个 `safeNum(v, fallback)` 工具函数，统一处理 null/undefined/NaN

### 修复 C：检查 CI 失败

1. 检查新增测试文件是否有语法/引用错误
2. 检查是否有 lint 违规（`var` 声明等）
3. 确认 Dependabot 的 nodemailer 9.x PR 是否需要处理
