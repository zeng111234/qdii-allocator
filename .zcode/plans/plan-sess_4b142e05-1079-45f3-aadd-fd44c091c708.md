# 安全修复计划：7个 Critical/High 问题

## 修复方案

### 1. Firebase 凭证暴露（CRITICAL）
**问题：** build-pages.js 把 Firebase Key 写入前端 HTML，任何人查看源码都能拿到。
**方案：** 不在前端嵌入 FIREBASE_KEY。改为通过 Web Server 代理 Firebase 请求，或至少把 Key 从前端移除。
**改动：** build-pages.js, docs/index.html.template, lib/web-server.js

### 2. 前端密码保护（CRITICAL）
**问题：** hash `1480551` 可秒破，或直接删 DOM 绕过。
**方案：** 移除假密码保护，改为显示免责声明。
**改动：** docs/index.html.template

### 3. Web Server 写接口无认证（CRITICAL）
**问题：** WEB_AUTH_TOKEN 不设置时，所有写接口完全开放。
**方案：** 启动时自动生成随机 Token 并打印到控制台，写接口强制要求 Token。
**改动：** lib/web-server.js

### 4. LLM 辩论结果 innerHTML XSS（HIGH）
**问题：** LLM 输出未经 HTML 转义就用 innerHTML 渲染。
**方案：** 在 regex 替换前先转义 HTML（与 renderMarkdown 一致）。
**改动：** docs/index.html.template

### 5. 外部数据 innerHTML XSS（HIGH）
**问题：** Twitter/外部信号数据未经转义就用 innerHTML 渲染。
**方案：** 对外部数据字段进行 HTML 转义。
**改动：** docs/index.html.template

### 6. SMTP TLS 验证被禁用（HIGH）
**问题：** `rejectUnauthorized: false` 导致邮件密码可能被中间人截获。
**方案：** 移除该配置，使用默认 TLS 验证。
**改动：** lib/mailer.js

### 7. LLM API Key 在 localStorage（HIGH）
**问题：** 任何 XSS 都能偷走 localStorage 中的 API Key。
**方案：** 通过 Web Server 代理 LLM 请求，前端不再直接存储 API Key。
**改动：** lib/web-server.js, docs/index.html.template

## 执行顺序
1. 先修简单的（2, 3, 4, 5, 6）— 纯代码修改
2. 再修 Firebase（1）— 改数据流
3. 最后修 LLM 代理（7）— 改架构
4. 每修一个写对应测试
5. 全部修完运行测试 + 推送
